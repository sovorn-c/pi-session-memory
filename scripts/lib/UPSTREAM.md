# Bigpowers verification-helper provenance

The traceability, blind-spot, and completeness algorithms below are vendored from the locally installed **Bigpowers 2.88.9** package under its MIT license. Their executable logic is retained; three upstream story-metadata comment lines are reworded so foreign Bigpowers story IDs are not misclassified as this repository's implementation tags, and trailing whitespace on three blank lines in the blind-spot engine is removed. The traceability and blind-spot engines also have narrowly scoped repository-input adapters/guards; the exact differences are documented below. Upstream and current local hashes are recorded after final implementation. The upstream license is preserved in `BIGPOWERS-MIT-LICENSE.txt`.

The two shell wrappers retain the official flags, exit semantics, engine arguments, and output paths, but resolve the project root from their own location instead of from the installed package. They use `PI_SESSION_MEMORY_PYTHON` when set, otherwise `python3.11`; the trace wrapper fails clearly if PyYAML is unavailable, rejects grep exit statuses other than 0 (matches) or 1 (no matches), checks its output paths and all wiki links before deleting anything, and invalidates only the generated matrix, Markdown report, wiki index, and story pages before an attempt and after engine failure. It rejects symlinked `specs/` and wiki output paths, and symlinked generated wiki files, so cleanup and writes cannot follow links or leave a success-shaped stale result outside the project. The blind-spot wrapper rejects a symlinked `specs/` directory or `specs/blind-spots.json` output before cleanup, removes the prior generated blind-spot report before an attempt, and requires both the execution-status file and generated traceability matrix before invoking the analyzer. Both wrappers default `PYTHONDONTWRITEBYTECODE=1`.

## Local input adapters and guards

This repository represents `epics[].wsjf` as an object with a numeric `score` field, while the upstream engine applies `float(epic.get("wsjf", 0))`. The local `_wsjf_score` adapter accepts both upstream scalar values and this repository's object form, then passes the same numeric score to the unchanged ranking/strict-coverage logic. A missing score, boolean, nonnumeric mapped value, or non-finite value fails before any matrix is written. Scalar conversion retains upstream behavior.

The trace producer's local output adapter derives `summary.coverage_percent` from its existing counts as `tagged_stories / total_stories * 100`, rejecting zero total. This supplies the existing completeness critic's optional metric; the critic's under-60% warning and 80%-or-higher FILLED thresholds and all blocker/severity rules remain unchanged.

The local trace engine also rejects empty/malformed epic inventories, missing/invalid capsule or legacy paths, paths escaping `specs/`, malformed story lists, story IDs outside the `eNNsNN` format, missing per-story development statuses, and grep errors that could leave the tag inventory incomplete. These guards prevent upstream defaults/skips from turning broken local inputs into a successful empty matrix. YAML parsing remains `safe_load`; grep remains an argument-vector subprocess (not a shell command). The blind-spot adapter now parses its YAML status input safely, validates the generated matrix shape, unique `eNNsNN` story IDs, nonempty story statuses, required links arrays, and link records with nonempty file/method strings, nonnegative integer lines, and high/medium/low confidence values. It requires a nonempty execution status for every matrix story before running the upstream finding checks. These input guards do not change oracle tiers, coverage matching, P0 threshold calculation, or blind-spot severities. The completeness critic adds a required-`jq` check and generated-input validation; its matrix guard requires a nonempty story inventory with valid story IDs, statuses, and links arrays. These guards do not change its coverage thresholds, classifications, or blocker/severity rules. Fixture tests assert scalar/object parity, fail-closed input boundaries, generated-matrix coverage classification, empty/malformed inventory rejection, and visible warning-only output.

The local trace engine therefore differs from its upstream source only by the documented WSJF adapter, required local-input/output guards, story/scenario comments, and harmless whitespace cleanup. Replacing or expanding these adapters requires a plan update and review; do not silently alter the upstream algorithms.
